# wsdr-studio Web (WebUSB + WASM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** wsdr-studio runs as a GitHub Pages site in Chrome (WebUSB, engine in WASM), with the Electron app built from the same engine and UI.

**Architecture:** The two-slot dispatch now in `src/main.cpp` moves into a transport-free `Studio` class. Native wraps it in the existing WebSocket server; the web build compiles it (plus engine, DSP, Wi-Fi, recorder) to WASM with pthreads, running in a dedicated worker whose main thread only relays messages and services libusb's forwarded WebUSB calls. The React UI gains a `Transport` seam: WebSocket (Electron) or the worker (web).

**Tech Stack:** C++20, Emscripten 4.0.12 (`-pthread`, JSPI, WASMFS + OPFS), libusb 1.0.29 (WebUSB backend), pocketfft (web) / FFTW (native), React 19 + Vite 8 + TypeScript, Node 24 test runner, GitHub Actions + Pages, coi-serviceworker.

**Spec:** `docs/superpowers/specs/2026-10-26-wsdr-web-design.md` (feasibility data: `wasm/README.md`)

## Global Constraints

- Every new source file starts with `// SPDX-License-Identifier: GPL-2.0-only` (vendored third-party files keep their own licence header + a LICENSE file beside them).
- Native behaviour is unchanged: `build/test_core` passes, `(cd web && npm test)` passes, `build/wsdr-studiod --headless-seconds 20 --pid 0xc812 --rate 5` exits 0, Electron still connects (`node tests/e2e.mjs` against a running app with view A open on the 8812CU).
- WASM link flags (all web targets): `-pthread -fwasm-exceptions -sJSPI -sINITIAL_MEMORY=512MB` (no memory growth), `-sDEFAULT_PTHREAD_STACK_SIZE=1MB`, `-sPTHREAD_POOL_SIZE=16`, `-sENVIRONMENT=web,worker -sMODULARIZE -sEXPORT_ES6`.
- The worker's main thread never blocks: no USB, no file I/O, no joins on it after startup.
- Pinned downloads are verified by sha256 (pattern: `LIBUSB_SHA256` in `wasm/build.sh`).
- Chrome ≥ 137 desktop; page served cross-origin isolated (COOP `same-origin`, COEP `require-corp`) natively by `wasm/serve.mjs`, by `coi-serviceworker` on Pages.
- Hardware available for verification: one 8812CU (USB 2, serial `123456`) only. Anything needing an 8812BU or two dongles is marked untested in docs, not faked.
- Hardware tests in Chrome use the CDP harness pattern from the spike (visible Chrome, profile `$SCRATCH/chrome-prof` with the dongle paired once by the user, port 9333).

## Review Focus

1. **Dongle unplugged while streaming (web):** the view shows "Adapter disconnected" and starts again by itself when replugged (new WebUSB session id, same serial). Pinned by a manual step in Task 8.
2. **Page reloaded or a second tab while streaming:** reload releases the device and Start works again; a second tab gets a "busy" banner, not a hang. Pinned by Task 3's e2e (`reload` case) and Task 8's manual step.
3. **Recording folder picker cancelled, or permission not granted:** Rec does not start, a banner says why, nothing is written to OPFS. Pinned by Task 7's unit test `record without folder`.
4. **rtw88 (or another program) holds the dongle:** the Start error says Chrome cannot take it and gives the `modprobe -r` line. Pinned by Task 8's second-tab check (the second tab's claim fails with exactly that banner).
5. **OPFS quota or write failure mid-recording:** the recording stops with the recorder's error in the `recorded` event and the partial file is still moved. Pinned by Task 7's unit test `move failure keeps file and reports`.

### Task 2: `Studio`, the transport-free two-slot dispatcher

**Files:**
- Create: `src/studio.h`, `src/studio.cpp`
- Modify: `src/main.cpp` (server handlers + 2 Hz tick delegate to `Studio`), `CMakeLists.txt` (`studio.cpp` in `studio_core`)
- Test: `tests/test_core.cpp` (`test_studio_dispatch`)

**Interfaces:**
- Consumes: `studio::Engine` (unchanged).
- Produces:
  ```cpp
  class Studio {
  public:
    static constexpr int kSlots = 2;
    using Send = std::function<void(std::string text)>;
    struct Out { Send broadcast_text; std::function<void(std::vector<uint8_t> &&)> broadcast_binary; };
    Studio(Out out, std::string record_dir, bool usb3_default, std::string home);
    void client_open(const Send &send);                 // hello, scan, then caps/settings/status per slot
    void client_text(const std::string &text, const Send &reply);
    void tick(bool any_clients, uint64_t client_drops);  // poll() both engines; status to everyone
    Engine &engine(int slot);
  };
  ```
  Behaviour is exactly today's `main.cpp` (`hello` carries `version 1, app, home, slots 2`; `devices` untagged, everything else tagged with `slot`; slot B rows get `f[6] |= 0x10`; `_`-prefixed commands → `unknown command`; bad slot → `slot must be 0 or 1`; non-object → `not a JSON object`; ids echoed).

### Task 3: The engine as a WASM module (`wsdr-core`)

**Files:**
- Create: `wasm/core.cpp`, `src/sources.cmake` (lists `STUDIO_CORE_SOURCES`, shared by both CMake files)
- Modify: `CMakeLists.txt` (use `sources.cmake`), `wasm/CMakeLists.txt` (target `wsdr-core`), `wasm/build.sh` (also fetches `nlohmann/json.hpp` v3.11.3 single include, pinned sha256, into `.deps`; builds `wsdr-core`; copies `wsdr-core.{js,wasm}` to `wasm/web/core/`), `src/device_scan.cpp`, `src/engine.cpp`
- Test: `tests/web-core.mjs` (CDP, hardware)

**Interfaces:**
- Consumes: `Studio` (Task 2), `Fft` pocketfft (Task 1).
- Produces (C exports, all non-blocking, called on the module's main thread):
  - `int core_start(const char *record_dir)` — mounts WASMFS OPFS at `record_dir` (`/recordings`), builds `Studio` (`home ""`, usb3 default on), starts a tick pthread calling `tick(true, 0)` every 500 ms. Returns 0, or 1 when the OPFS mount fails.
  - `void core_client_open()`, `void core_text(const char *json)` — forward to `Studio`; replies and broadcasts both go to the page.
  - Outgoing (called from any pthread, delivered on the main thread with `MAIN_THREAD_ASYNC_EM_ASM`, heap copies freed after delivery): `Module.onCoreText(string)`, `Module.onCoreBinary(Uint8Array)` (a copy).
  - Worker protocol (page ↔ worker), used by Task 4: page → worker `{t:'open'}` (a client connects: `core_client_open`), `{t:'text', text}` (a command); worker → page `{t:'ready'}` (module loaded, `core_start` returned 0), `{t:'fatal', msg}` (load or OPFS mount failed), `{t:'text', text}`, `{t:'bin', buf}` (`buf` transferred).
- `__EMSCRIPTEN__` seams: `scan_devices()` takes `speed_mbps` from `libusb_get_device_speed` (HIGH 480, SUPER 5000, SUPER_PLUS 10000), `port` from `libusb_get_port_numbers`, `can_open = true`, `driver`/`controller` empty, no sysfs. `Engine::disk_free()` returns -1. The `busy` open failure's message becomes: `Chrome could not claim the adapter: another program or the kernel driver holds it. On Linux: sudo modprobe -r rtw88_8822bu rtw88_8822cu (or blacklist them, see the README).`

- [ ] **Step 1: Write the failing test** `tests/web-core.mjs`: serves `wasm/web` (via `wasm/serve.mjs`), loads `core/test.html` (a 20-line page that starts the core in a worker and exposes `window.core.text(json)` and the event log), then:

  - `open` slot 0 (`pid 0xc812`, `rate_sel 4`) acks within 60 s; over the next 15 s, rows for slot 0 arrive at ≥ 20 per second and the last `status` has `rx.restarts == 0` and `ring_dropped == 0`;
  - `open` slot 1 on the same adapter → error whose `msg` starts with `every adapter of this kind is open` (claims);
  - page reload, `open` slot 0 again → ack (the device was released).
- [ ] **Step 2:** Run `node tests/web-core.mjs`; expected: FAIL (no `core/wsdr-core.js`).
- [ ] **Step 3:** Implement `wasm/core.cpp`, the seams, the `wsdr-core` target and `build.sh` changes. `core/worker.js` + `core/test.html` live in `wasm/web/core/` and speak the worker protocol above.
